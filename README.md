# md2gostdocx

Сборка сдаточного DOCX из Markdown-документации по профилю оформления ГОСТ 19.

Markdown лежит в git и читается на GitHub, а инструмент превращает его в документ
для Word: Times New Roman 12, таблицы во всю ширину полосы набора, чёрные границы
0,5 pt, жирная шапка. Перед сборкой документ проверяется линтером.

Всё выполняется на вашем компьютере. Документы никуда не отправляются.

## Установка

Нужны две программы: **pandoc** и **uv** (второй приносит с собой Python).

```bash
# macOS
brew install pandoc uv

# Windows
winget install --id JohnMacFarlane.Pandoc
winget install --id=astral-sh.uv -e
```

Затем сам инструмент и проверка окружения:

```bash
uv tool install md2gostdocx
md2gostdocx doctor
```

## Использование

```bash
md2gostdocx build ТЗ.md              # DOCX появится рядом с исходником
md2gostdocx check docs --recursive   # только проверка, без сборки
md2gostdocx doctor                   # что установлено, чего не хватает
md2gostdocx profiles                 # доступные профили оформления
```

Коды возврата — стабильный интерфейс для CI и pre-commit: `0` успех,
`1` предупреждения при `--strict`, `2` ошибки в Markdown, `3` ошибка pandoc,
`4` сломано окружение, `64` ошибка использования.

## Что проверяет линтер

| Код | Что нашёл |
|---|---|
| `IMG001` | файл изображения не найден |
| `IMG002` | абсолютный путь к изображению — такой файл уедет внутри DOCX |
| `HDR001` | нет раздела верхнего уровня |
| `HDR002` | нарушена иерархия заголовков |
| `META001` | не заполнен `title` в YAML-метаданных |
| `TBL001` | в таблице разное число ячеек |
| `MMD001` | Mermaid-диаграмма попадёт в DOCX текстом |
| `HTML001` | после `<div class=…>` нет пустой строки — содержимое блока потеряется |

## Состояние

Ранняя версия, 30 тестов. Работает сборка с профилем ГОСТ 19, проверка
Markdown, диагностика окружения, семантические блоки и титульный лист из
YAML-метаданных.

В работе: веб-интерфейс с редактором и предпросмотром, лаунчеры для установки
без терминала, рендеринг Mermaid в PNG.

Оформление ещё ни разу не проверялось в настоящем Microsoft Word — все
проверки идут на уровне OOXML.

Планы и решения — в [docs/PLAN-md2gostdocx.md](docs/PLAN-md2gostdocx.md) и
[docs/adr-01-frontend-stack.md](docs/adr-01-frontend-stack.md).

## Разработка

```bash
PYTHONPATH=src python3 -m pytest tests -q
PYTHONPATH=src python3 -m md2gostdocx.cli doctor
```

Тесты проверяют инварианты OOXML, а не байты: они переживают обновление pandoc.
Microsoft Word в тестах не участвует — он остаётся судьёй на приёмке.
